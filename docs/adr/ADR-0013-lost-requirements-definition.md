# ADR-0013 — Что считать потерянным элементом?

- Статус: Proposed (рабочий вариант, ждёт решения пользователя)
- Дата: 2026-10-04
- Supersedes: —
- Связанные требования: [DEC-13](../spec/defaults.md), PTH-US-055, PTH-FR-079…081, PTH-AC-031, PTH-AC-032, PTH-AC-035

## Контекст

Пользователь уточнил: потерянным является не только требование, не используемое в коде, но и user story без отражения в ФТ или ADR. Нужен однозначный критерий, который вычисляется из связей, без ручного статуса.

## Рассмотренные варианты

1. Рабочий вариант: (а) FR, NFR, AC без связи implements от COMMIT и без обоснованного исключения; (б) US без refines от ФТ и без motivates к ADR; (в) фрагменты источника без сопоставления.
2. Альтернатива: считать потерянным и отсутствие TEST — расширит список и добавит шум.
3. Альтернатива: считать потерянным только отсутствие кода — скроет user story без отражения в ФТ/ADR.

## Решение и причины

Для старта разработки взят вариант 1. Отсутствие TEST отображается отдельным состоянием «не проверено». Это предложение, а не согласованное решение.

## Последствия

Список потерянных вычисляется по графу связей; состояние не хранится вручную. Обоснованное исключение (`exemption_reason` в ревизии) выводит требование из списка в «исключено».

## Условия пересмотра

Решение пользователя по DEC-13 или появление данных о ложных срабатываниях на реальном проекте.
