# Роли, сценарии и User Story

> Извлечено из `Project_Traceability_System_Spec_v0.1.md`. Не редактировать вручную: `python3 scripts/sync_spec.py`.

## 2. Роли и сценарии

### 2.1. Роли

| Роль | Основные задачи |
| --- | --- |
| Владелец продукта / проекта | Принимает исходную спецификацию, контролирует полноту и изменения |
| Аналитик | Декомпозирует БТ/US/ФТ/НФТ, устраняет пробелы и противоречия |
| Архитектор | Ведёт ADR, компоненты, контракты и архитектурное покрытие |
| Разработчик | Получает контекст, реализует требования, связывает код и коммиты |
| QA / приёмщик | Создаёт проверки и ПСИ, фиксирует результаты |
| Claude / другой ИИ | Действует от сервисного аккаунта с определёнными правами |
| CI / Git-коннектор | Передаёт коммиты, проверки и технические свидетельства |
| Администратор | Управляет доступом, интеграциями, схемами и восстановлением |

Один человек может совмещать все человеческие роли. Профессия не равна permission-role: права задаются отдельно. ИИ не получает права владельца автоматически.

### 2.2. Сквозной основной сценарий

1. Пользователь обсуждает будущий продукт с ИИ в любом доступном чате.
2. Пользователь получает и корректирует текст спецификации.
3. Пользователь явно принимает конкретную редакцию текста.
4. Claude получает текст и указание импортировать его в выбранный проект.
5. Скилл создаёт SourceDocument, ImportSession и черновой ChangeSet.
6. Claude извлекает сущности, сопоставляет существующие ID, предлагает связи и сохраняет основания.
7. Сервер проверяет модель; Claude сообщает о пропусках, неоднозначностях и конфликтующих ID.
8. После разрешения блокирующих вопросов ChangeSet применяется в рамках ранее предоставленной политики. Повторное ручное подтверждение точной раскладки принятого текста не обязательно.
9. Пользователь видит реестр, исходные цитаты, граф и отчёт импорта.
10. При новой задаче Claude запрашивает ContextBundle, реализует изменения и связывает их с задачей, требованиями и коммитами.
11. При изменении требования UI/скилл показывает diff, влияние и требуемые перепроверки.
12. Проверки и ПСИ строятся из принятого состояния реестра; результаты привязаны к коду и baseline.

## 3. User Story

ID этого документа: PTH-US-NNN, PTH-FR-NNN, PTH-NFR-NNN и PTH-AC-NNN. Они относятся к разрабатываемому сервису. ID импортированных проектов имеют собственный project_key.

Приоритет P0 — обязателен для первого сквозного релиза; P1 — следующий релиз; P2 — расширение. P0 не означает, что story должна быть сделана в первом спринте.
