# Правила ID

Спека использует стабильные ID. Строки ниже — текущие диапазоны; реестр с местом каждого ID — в [requirements-registry](requirements-registry.md).

| Префикс | Тип | Диапазон | Где определён |
| --- | --- | --- | --- |
| PTH-US-NNN | User Story | 001–056 | [user-stories](user-stories.md), приложение A в [acceptance](acceptance.md) |
| PTH-FR-NNN | Функциональное требование | 001–084 | [functional-requirements](functional-requirements.md) |
| PTH-NFR-NNN | Нефункциональное требование | 001–021 | [nonfunctional](nonfunctional.md) |
| PTH-AC-NNN | Приёмочный сценарий | 001–035 | [acceptance](acceptance.md) |
| DEC-NN | Решение, требующее принятия | 01–13 | [defaults](defaults.md) |
| SK-NN | Скилл | 01–13 | [context-and-mcp](context-and-mcp.md), [паспорта](skills/index.md) |
| ADR-NNNN | Архитектурное решение | по порядку | [adr/index](../adr/index.md); ADR-00NN соответствует DEC-NN |

## Правила

1. Номер не переиспользуется и не меняется. Снятое требование помечается в тексте как снятое с причиной и остаётся в реестре.
2. Новое требование получает следующий свободный номер своего типа. Проверь реестр, прежде чем выбрать номер.
3. Смысл принятого требования меняется только новой редакцией с записью в [истории](history.md). Правка, не меняющая смысла (опечатка, оформление), вносится напрямую в исходник.
4. ID в спеке — идентификаторы документа. Серверные ID артефактов продукта выдаёт сервис; в документах разработки их не придумываем.
5. После добавления или изменения ID в исходнике запусти `python3 scripts/sync_spec.py` и проверь реестр.
