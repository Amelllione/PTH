# Запись результата в Git

Корень репозитория пока не под Git. Когда он будет инициализирован, фиксируй результат так. Если Git недоступен или коммит не разрешён, подготовь текст и назови причину.

## Перед записью

1. Посмотри `git status` и diff. Включай только файлы текущей задачи. Не коммить чужие изменения и секреты.
2. Убедись, что спека (исходник), извлечения, реестр, ADR и проверки обновлены в пределах задачи. Не отмечай непроверенное готовым.
3. Укажи только фактически запущенные проверки и их результаты.
4. Коммит создаётся только по явной просьбе пользователя.

## Формат сообщения

```text
<тип>: <наблюдаемый результат> [PTH-FR-NNN]

Что сделано:
- Изменены <поведение, контракт, файлы>.

Основание:
- PTH-US-NNN, PTH-FR-NNN, PTH-AC-NNN; DEC или ADR при наличии.

Проверено:
- <команда или сценарий> — <результат>.

Ограничения:
- <что не проверено; «нет» только при полном покрытии задачи>.
```

`<тип>` — по соглашению репозитория; если его нет, используй `feat`, `fix`, `docs` или `refactor`. Не добавляй ID, которых изменение не касается.

## Git trailers (после появления продукта)

Совпадают с [разделом 13.4 спеки](spec/git-trace.md):

```text
Project-Artifact: <ID>@<revision>
Project-Task: <ID>
Project-Change: <uuid>
Project-Context: <uuid>
```

Trailers — claims автора. Сервер проверяет их сам. До этапа E4 используется временный manifest в репозитории (§18.4); при импорте исходные SHA сохраняются.
