# pth-project-context (SK-02)

Собирает краткий контекст из PTH по ID требования или по всему проекту. Только читает данные.

## Вход

- Ключ проекта (например `PTH`) и, если есть, ID артефакта (`PTH-FR-012`) или тип (`US`, `FR`, `NFR`, `AC`).
- `PTH_URL` и `PTH_TOKEN` (право чтения достаточно).

## Шаги

1. Проверь доступ: `python3 sdk/pth_client.py me`. Если ключ не из этого проекта, сообщи, что данные по нему недоступны.
2. Если дан ID, собери контекст одной командой: `python3 sdk/pth_client.py context <KEY> <ID> --depth 2`. В ответе: карточка (`focus`), соседи и связи (`graph`), причина попадания в потерянные (`lost`), исключение (`excluded`), черновики (`draft_changesets`) и полнота (`completeness`).
3. Если `completeness` равно `truncated`, так и скажи: граф неполный, нужна меньшая глубина или точный запрос.
4. Если ID не дан или не найден, найди по тексту: `python3 sdk/pth_client.py search <KEY> "<запрос>" [--type FR]`.
5. Общая картина проекта: `python3 sdk/pth_client.py status <KEY>`. Укажи число потерянных, исключённых и черновиков.

## Выход

Короткая сводка на русском: что это за требование, с чем связано, что не связано с кодом, есть ли незастывшие черновики, какие данные неполные. Укажи ID, по которым давал вывод.

## Границы

- Только чтение. Не применяй черновики, не импортируй и не создавай артефакты.
- Не утверждай, что требование реализовано, по одному наличию связи `implements`: статус проверки в PTH вычисляется отдельно.
- Если в ответе есть ошибка API, передай пользователю код и текст. Не подменяй данные догадками.
- Если данных мало, так и скажи, не дополняй контекст из памяти.
