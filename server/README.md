
## Где хранятся данные

- По умолчанию SQLite-файл `server/pth.db`, создаётся при первом запуске из папки `server`. Путь задаётся `PTH_DATABASE_URL`, например `postgresql://…` (драйвер нужно установить, миграций пока нет).
- Токены LM Studio (`LM_API_TOKEN`) хранятся только в окружении процесса, в базу не пишутся.
- API-ключи PTH хранятся в таблице `api_keys` как SHA-256 от токена, сам токен не сохраняется.
- Удалить базу — значит удалить `pth.db`. Резервной копии и миграций пока нет.

## Модель данных по модулям (`pth/models/`)

| Модуль | Таблицы | Что хранит |
|---|---|---|
| `accounts.py` | `projects`, `api_keys` | проекты, ключи доступа и их роли |
| `artifacts.py` | `artifacts`, `artifact_revisions`, `relations` | требования и решения, неизменяемые ревизии, связи |
| `work.py` | `import_sessions`, `changesets`, `extraction_jobs` | журнал импортов с исходным текстом, черновики изменений, фоновое выделение |
| `common.py` | — | `new_uid`, `utcnow` |

Все модули реэкспортируются из `pth.models`, поэтому импорты в коде не меняются.

## Резервное копирование

```bash
cd server && .venv/bin/python scripts/backup_db.py
```

Копия пишется в `server/backups/` без остановки сервера и сразу проверяется: `integrity_check` и версия схемы. Восстановление: остановить сервер и заменить `pth.db` копией.

## Версии схемы

Миграции в `pth/migrations.py` применяются при запуске по порядку и записываются в `schema_version`. Текущая версия — 2 (свидетельства проверок и базовые снимки).
